Prerequisites:

  • return \(G_t\), TD error \(\delta_t\), Sarsa
  • dot products and the derivative of a square
Recurring question: how can one update improve predictions for states we have never visited?

Sources: Sutton & Barto (2018), Chapters 9–10; David Silver, Lecture 6: Value Function Approximation

Ask where a table becomes impractical: continuous temperature, position and velocity, camera observations. The key shift is shared parameters, not simply a smaller data structure. The lecture first makes sharing visible, then derives one reusable update whose target is supplied by the RL algorithm. Prediction assumes a fixed policy until the control section. Large State Spaces

State descriptionStates
10 binary variables\(2^{10}=1{,}024\)

Position and velocitycontinuous
Camera imagevast

A table cannot predict a state it has never seen.

Replace the table by a function with \(d\) weights: \[\hat v(s,\mathbf w)\approx v_\pi(s)\] \[\hat q(s,a,\mathbf w)\approx q_\pi(s,a)\]

  • \(d\) is much smaller than the number of states
  • one update changes many predictions

Sources: Sutton & Barto (2018), §9.1; David Silver, Lecture 6

Memory: one 8-byte value for each of 2^30 states is exactly 8 GiB, before actions are counted; an action-value table multiplies this. Storage is not the only problem: an unvisited table entry has no evidence at all. A function transfers evidence through shared weights, so an update at one state changes the prediction at others. Whether that transfer helps depends on the representation, which is the subject of most of this lecture. Compression helps storage; generalisation helps learning. Modern neural networks may have more parameters than samples; the point is to exploit structure in the mapping from states to returns, not merely to be small.

Linear Function Approximation

Feature Vectors

A feature vector describes state \(s\) with \(d\) numbers: \[\mathbf x(s)=\big(x_1(s),\,x_2(s),\,\dots,\,x_d(s)\big)^{\!\top}\]

Simple Mountain Car features:

\[\mathbf x(s)=\big(1,\ \text{scaled position},\ \text{scaled velocity}\big)^{\!\top}\]
  • the constant 1 lets the approximator learn an intercept
  • features may be nonlinear in \(s\): polynomials, tiles, radial basis functions
  • scale features to comparable ranges

Sources: Sutton & Barto (2018), §9.4–9.5; David Silver, Lecture 6

Features are the only thing the approximator sees about the state. Scaling matters because one step size multiplies every feature: if position is in metres and velocity in metres per second with very different ranges, the weights of the larger feature dominate the update. Normalising both coordinates to about [−1, 1] keeps the features dimensionless. With dimensionless features, weights carry reward units. A one-hot feature for every state recovers the table as a special case, so linear approximation is a strict generalisation of the tabular methods from Lectures 4 and 5.

Linear Value Function

A weighted sum of features: \[\hat v(s,\mathbf w)=\mathbf w^{\top}\mathbf x(s)=\sum_{i=1}^{d}w_i\,x_i(s),\qquad \nabla_{\mathbf w}\hat v(s,\mathbf w)=\mathbf x(s)\]

Example

\(\mathbf x(s)=(1,\ 0.5,\ {-1})^{\top}\)
\(\mathbf w=(2,\ {-1},\ 0.5)^{\top}\)

\[\hat v(s,\mathbf w)=2-0.5-0.5=1\]

Two length-3 vectors give one scalar.

“Linear” refers to the weights. The features may be any functions of the state.

Sources: Sutton & Barto (2018), §9.4; David Silver, Lecture 6

Calculate each contribution aloud and check the signs: 2×1 = 2, (−1)×0.5 = −0.5, 0.5×(−1) = −0.5. The third feature is negative but its weight is positive, so that term lowers the prediction; do not interpret a weight without knowing its feature convention. Both vectors are d-by-1; the gradient has d entries, one partial derivative per weight. Because the gradient is exactly the feature vector, linear methods are easy to inspect and have the strongest theory. These numbers are reused in the weight-update check. Linear in the weights is not linear in the state: polynomial features x(s) = (1, x, x²) draw a bowl or an inverted bowl, yet ∇v̂ = (1, x, x²) whatever the weights are. For Mountain Car with s = (p, v), a quadratic basis is x(s) = (1, p, v, p², pv, v²); higher orders add flexibility but amplify scaling problems and extrapolate badly outside the visited region.

Mean Squared Value Error

\[\overline{\mathrm{VE}}(\mathbf w)=\sum_{s}\mu(s)\big[v_\pi(s)-\hat v(s,\mathbf w)\big]^2,\qquad \mu(s)\ge 0,\ \ \sum_s\mu(s)=1\]

  • \(\mu(s)\): how much state \(s\) counts
  • on-policy: the fraction of time \(\pi\) spends in \(s\)

One constant \(w\); \(v_\pi(A)=0\), \(v_\pi(B)=10\)

\(\mu(A)\)\(\mu(B)\)Best \(w\)
0.90.11
0.50.55
A low average error can hide a large error in a rare state.

Sources: Sutton & Barto (2018), §9.2

Differentiate 0.9w² + 0.1(10 − w)² to get w = 1; its squared error at B is 81 even though it is optimal for this model and weighting. Equal weights give w = 5. Neither repairs the missing capacity: one parameter is trying to represent two different values. The weighting defines what is optimised, not what is acceptable in a safety-sensitive application. v_π is the true expected return under the fixed policy, not a sampled return or a bootstrap estimate, so VE cannot be computed during learning; it is the yardstick used in the random-walk demonstration, where the true values are known.

Stochastic Gradient Descent

For a target \(U_t\), reduce the sample error \(\tfrac12\big[U_t-\hat v(S_t,\mathbf w_t)\big]^2\):

\[\mathbf w_{t+1}=\mathbf w_t+\alpha\big[U_t-\hat v(S_t,\mathbf w_t)\big]\nabla_{\mathbf w}\hat v(S_t,\mathbf w_t)\]

Linear case: \[\mathbf w_{t+1}=\mathbf w_t+\alpha\big[U_t-\hat v(S_t,\mathbf w_t)\big]\,\mathbf x(S_t)\] step size \(\times\) prediction error \(\times\) features

  • the RL method supplies the target \(U_t\); the approximator supplies the gradient
  • weights of inactive (zero) features do not change

Sources: Sutton & Barto (2018), §9.3–9.4; David Silver, Lecture 6

Hold U_t fixed while differentiating. The ½ cancels the 2 from the square. The derivative of the error is −(U_t − v̂)∇v̂; gradient descent subtracts it, so a positive error moves the prediction up. If U_t is an unbiased sample of v_π(S_t), for example a Monte Carlo return, this is true SGD on VE and converges to a local optimum under the usual decreasing step-size conditions. A TD target depends on w itself; treating it as fixed gives a semi-gradient, discussed in the next section. With dimensionless features, α is dimensionless.

Give thirty seconds before revealing. Answer 1.45. The third weight falls, yet because its feature is negative the prediction rises. Choosing the Step Size

Repeated updates at one state towards a fixed target \(U\):

\[U-\hat v'=\big(1-\alpha\lVert\mathbf x(s)\rVert^2\big)\big(U-\hat v\big)\]
  • the error shrinks only if \(0<\alpha\lVert\mathbf x(s)\rVert^2<2\)
  • Quick Check state: \(\lVert\mathbf x\rVert^2=2.25\), so \(\alpha<0.89\)

Five fixed targets \(U=1+x\) at \(x=-1,\,-0.5,\,0,\,0.5,\,1\). Model \(\hat v=w_0+w_1x\) from \(\mathbf w=\mathbf 0\), samples visited in a fixed cycle.

\(\alpha\)After 20 updatesAfter 200 updates
0.1MSE 0.074w = (1.00, 1.00)
1.5MSE 8.06MSE 4.3 × 10⁷
Too small learns slowly; too large diverges, even with fixed targets. Scale \(\alpha\) to the features.

Sources: Sutton & Barto (2018), §9.3 and §9.6

Derivation: after one update the prediction at the same state moves by αδ‖x(s)‖², so the remaining error U − v̂ is multiplied by 1 − α‖x(s)‖². It shrinks monotonically for α‖x‖² ≤ 1, oscillates but shrinks between 1 and 2, and grows beyond 2. For the Quick Check state (‖x‖² = 2.25) that means α < 2/2.25 ≈ 0.89. The table is deterministic cyclic SGD on a perfectly representable data set, with no environment and no TD targets: at α = 0.1, 20 updates give w ≈ (0.923, 0.632), MSE 0.0738, and 200 updates reach (1.000, 1.000); at α = 1.5, 20 updates give w ≈ (−1.26, −1.44), MSE 8.06, and 200 updates give w ≈ (−3621, −7730), MSE ≈ 4.3×10⁷. For this cycle the boundary lies between α = 1.4 (converges) and α = 1.45 (grows); with several samples the limit depends on how their features overlap, not only on one ‖x‖². Sutton and Barto (§9.6) suggest α = 1/(τ E[xᵀx]) to learn from about τ similar experiences; tile coding's α = η/m is that rule with ‖x‖² = m. Moving TD targets make the choice more delicate, not less.

Prediction with Approximation

Monte Carlo and TD Targets

Gradient Monte Carlo

\[U_t=G_t\]

An unbiased sample of \(v_\pi(S_t)\); wait until the episode ends.

Semi-gradient TD(0)

\[U_t=R_{t+1}+\gamma\hat v(S_{t+1},\mathbf w_t)\]

Learn after one step; bootstrap from the current estimate.

TD error and linear TD(0) update: \[\delta_t=R_{t+1}+\gamma\hat v(S_{t+1},\mathbf w_t)-\hat v(S_t,\mathbf w_t),\qquad \mathbf w_{t+1}=\mathbf w_t+\alpha\,\delta_t\,\mathbf x(S_t)\]

Sources: Sutton & Barto (2018), §9.3; David Silver, Lecture 6

Both methods use the same parameterised prediction and the same gradient; they differ only in how the target is built. For a fixed policy a complete return is an unbiased sample of the value, but it can have high variance and needs the end of the episode. TD substitutes an approximate next value and can update immediately; its target is generally biased by the approximation and usually less variable. Do not claim TD always has smaller total error. A worked check: v̂(S_t) = 0.8, R = 0, v̂(S_{t+1}) = 1.1, γ = 0.9 gives δ = 0.19, so with α = 0.1 every active weight moves by 0.019 times its feature.

Why “Semi-Gradient”?

The TD target also depends on \(\mathbf w\). The full gradient of \(\tfrac12\delta_t^2\) is

\[\delta_t\big[\gamma\nabla_{\mathbf w}\hat v(S_{t+1},\mathbf w)-\nabla_{\mathbf w}\hat v(S_t,\mathbf w)\big]\]

Semi-gradient TD keeps only the current-state term: it treats the target as a constant.

Which quantity is held fixed inside the TD update?

Sources: Sutton & Barto (2018), §9.3 and Chapter 11

The current weights influence both predictions, so the full derivative has two terms; semi-gradient TD keeps only the derivative of the current prediction. That does not mean the target never changes: the next update recomputes it with the new weights. Semi-gradient methods are not true gradient descent on any objective, yet linear on-policy TD(0) still converges (to the TD fixed point, later in this lecture), often faster than MC. Distinguish the gradient of this sampled squared TD error from the gradient of the squared expected Bellman error: in stochastic environments these are different objectives, and the latter raises a double-sampling problem. Residual-gradient methods are not obtained by relabelling ordinary TD.

Terminal Transitions

True termination

No future return remains (the car reaches the goal).

\[U_t=R_{t+1}\] \[\delta_t=R_{t+1}-\hat v(S_t,\mathbf w)\]

Time limit

Recording stopped, but the task would continue.

\[U_t=R_{t+1}+\gamma\hat v(S_{t+1},\mathbf w)\]

Bootstrap from the observed \(S_{t+1}\).

A finite-horizon task is different: put the remaining time in the state; its horizon is a true termination.

Sources: Sutton & Barto (2018), §3.3 and §10.1

This prevents a common implementation error: treating every data-collection boundary as a zero-value absorbing state. For an artificial cutoff in a continuing task, zeroing the bootstrap invents an ending that is not part of the problem. For an explicitly finite-horizon task, reaching the horizon is a real termination and the remaining time may be needed for a Markov state. The choice follows the task definition, not the name of a library flag. At true termination Sarsa selects no next action. A useful unit test: give the final transition a deliberately huge fake next value and check that it cannot leak into the target.

Choosing Features

Tile Coding

Overlay \(m\) offset grids (tilings). Each state activates one tile in each tiling:

\[\hat v(s,\mathbf w)=\sum_{i\,\in\,\text{active}(s)}w_i\]
  • binary features, exactly \(m\) active: cheap to compute
  • nearby states share some tiles, distant states none
  • one tiling is state aggregation

With \(\lVert\mathbf x(s)\rVert^2=m\), choosing \(\alpha=\eta/m\) moves the visited prediction by \(\eta\,\delta\).

Sources: Sutton & Barto (2018), §9.5.4; David Silver, Lecture 6

If the active tile indices are 7, 42, 81 and 116, then v̂(s) = w_7 + w_42 + w_81 + w_116 and each transition updates only those four weights. Without dividing by m, one sample changes the visited prediction about m times more than intended. The offsets give a resolution finer than one tile while keeping broad generalisation; Sutton and Barto recommend asymmetric offsets in more than one dimension. The statement about η assumes no hash collisions. For Mountain Car the tilings cover position and velocity together, as in the control demonstration later.

Interactive: Tile Coding

Four tilings of a position \(x\in[0,1]\). Tile width ¼; offsets of 0, ¼, ½ and ¾ of a tile. Each of the 19 tiles is one binary feature.

Move x slowly across 0.5. How many tiles change at once, and how much is shared with x′?

The tiles are numbered 1–19 across the four tilings (tiling 1 has four tiles, the shifted tilings five, with part-tiles at the ends); each number is one binary feature, as on the previous slide. Defaults: x = 0.49 activates features 2, 7, 12 and 17, so v̂(x, w) = w₂ + w₇ + w₁₂ + w₁₇, and shares 7, 12 and 17 (3 of 4) with x′ = 0.55. Moving x across 0.50 switches only the unshifted tiling first (feature 2 → 3); x and x′ then share all four tiles. Moving further, one tiling switches at a time: tiling 4 at 0.5625 (x = 0.57 shares 3), tiling 3 at 0.625 (0.63 shares 2), tiling 2 at 0.6875 (0.69 shares 1). Because all features are binary, an update at x changes v̂(x′) by (shared tiles)/4 of the change at x: with x = 0.49, 1/4 at x′ = 0.3, 2/4 at 0.62, none at 0.75. Generalisation therefore falls off gradually with distance instead of all-or-nothing, at a resolution of 1/16 although each tile is 1/4 wide. The right endpoint x = 1 belongs to the last tile in each tiling (features 4, 9, 14, 19).

Sharing Is an Assumption

Aliasing

  • same position, opposite velocity: different best actions
  • drop velocity and they merge; more training cannot separate them

Smoothness

  • nearby states can lie either side of a cliff or a goal
  • broad features blur the boundary; narrow ones stop transfer
The best representation supports the distinctions the policy needs to make.

Sources: Sutton & Barto (2018), §9.5 and §10.1

Separate two failures. Aliasing loses information: genuinely different decision situations get the same features, which the Mountain Car position-only rule illustrated. Capacity is different: the input may be informative but the function class too coarse. Feature engineering or learned features can fix capacity, but cannot recover information that is absent unless history supplies it. Smoothness is a modelling choice, not a fact about value functions: collisions, checkmate or constraint violations create sharp changes. Rough guide: too few broad features give nearly equal values to different states; useful local features transfer to relevant neighbours; too many narrow features approach a sparse table; flexible nonlinear models can fit complex structure but may be unstable. Low training loss does not distinguish these.

Control with Approximation

Approximate Action Values

One weight vector per discrete action: \[\hat q(s,a,\mathbf W)=\mathbf w_a^{\top}\mathbf x(s),\qquad \hat{\mathbf q}(s)=\mathbf W\mathbf x(s)\]

  • \(\mathbf W\): one row per action
  • \(\varepsilon\)-greedy acts on \(\hat{\mathbf q}(s)\) as it did on a table

Example with \(\mathbf x(s)=(1,\ 0.5)^{\top}\):

Action\(\mathbf w_a\)\(\hat q\)
Left\((1,\ 2)\)2.0
Right\((2,\ {-1})\)1.5

Sources: Sutton & Barto (2018), §10.1; David Silver, Lecture 6

For |A| discrete actions and d features, W is |A|-by-d, x is d-by-1 and the output has one entry per action. Left: 1 + 2×0.5 = 2.0; right: 2 − 0.5 = 1.5; greedy chooses Left. With separate linear rows, updating the chosen action's row changes that action's predictions across states but leaves the other rows unchanged. A neural network with shared hidden layers does not have that property. Joint state–action features x(s, a) with a single weight vector are an equivalent general form; one row per action is the most transparent.

Semi-Gradient Sarsa

\[\delta_t=R_{t+1}+\gamma\,\hat q(S_{t+1},A_{t+1},\mathbf W)-\hat q(S_t,A_t,\mathbf W)\] \[\mathbf w_{A_t}\leftarrow\mathbf w_{A_t}+\alpha\,\delta_t\,\mathbf x(S_t)\]

  1. Take \(A_t\); observe \(R_{t+1}\) and \(S_{t+1}\)
  2. Choose \(A_{t+1}\) \(\varepsilon\)-greedily from \(\hat{\mathbf q}(S_{t+1})\)
  3. Compute \(\delta_t\); update row \(A_t\) only
  4. Continue from \((S_{t+1},A_{t+1})\)

At termination: \(\delta_t=R_{t+1}-\hat q(S_t,A_t,\mathbf W)\), and no next action.

Sources: Sutton & Barto (2018), §10.1

The next action must be chosen before the target is formed, because its value is part of the target. If exploration picks a poor action, Sarsa evaluates that exploratory behaviour: the target is on-policy. Replacing the selected action's value by a maximum gives a Q-learning target and makes the method off-policy, which matters for the deadly triad later. As the policy improves the prediction target moves, so fixed-policy convergence results do not automatically carry over to control: with linear features Sarsa can chatter near a good solution rather than converge.

Quick Check: One Sarsa Update

Left row \(\mathbf w=(1,\ 2)^{\top}\), \(\mathbf x=(1,\ 0.5)^{\top}\), so \(\hat q=2\).

Reward \(-1\). The selected next action has \(\hat q=4\). \(\gamma=0.9\), \(\alpha=0.1\).

What is \(\Delta\mathbf w_{\text{Left}}\)?

Answer (0.06, 0.03). δ = −1 + 0.9×4 − 2 = 0.6; αδ = 0.06; multiply by the features. The current prediction rises by 0.075 because ‖x‖² = 1.25. Distractors: (−0.3, −0.15) wrongly treats the transition as terminal (δ = −3); (0.06, 0.06) forgets to multiply by the features. Only the Left row changes; the Right row (2, −1) is untouched.

Batch and Deep Value Methods

Least Squares and LSTD

Fixed targets

\[\min_{\mathbf w}\tfrac12\lVert\mathbf X\mathbf w-\mathbf y\rVert^2\] \[\mathbf X^{\top}\mathbf X\,\mathbf w=\mathbf X^{\top}\mathbf y\]

\(\mathbf X\): one feature row per sample; \(\mathbf y\): targets. Solve with QR or SVD.

Example: \(x=(-1,0,1)\), \(y=(0,1,2)\), \(\mathbf x=(1,x)^{\top}\) give \(\mathbf X^{\top}\mathbf X=\operatorname{diag}(3,2)\), \(\mathbf X^{\top}\mathbf y=(3,2)^{\top}\), \(\mathbf w=(1,1)^{\top}\).

TD fixed point (LSTD)

\[\mathbf A=\sum_t\mathbf x_t\big(\mathbf x_t-\gamma\mathbf x_{t+1}\big)^{\!\top}\] \[\mathbf b=\sum_t R_{t+1}\,\mathbf x_t,\qquad \mathbf A\mathbf w=\mathbf b\]

\(\mathbf x_t=\mathbf x(S_t)\); set \(\mathbf x_{t+1}=\mathbf 0\) at termination.

Sources: Sutton & Barto (2018), §9.8; David Silver, Lecture 6

For fixed targets, setting the gradient Xᵀ(Xw − y) to zero gives the normal equations; the example fits y = 1 + x exactly. A unique solution needs full rank: redundant or never-observed features make XᵀX singular. QR or SVD is preferable to forming an explicit inverse, and regularisation changes the objective. Complete returns can serve as Monte Carlo targets. LSTD is not ordinary regression with frozen TD targets: substitute the weight-dependent bootstrap into the expected TD update, set it to zero, and obtain A w = b. It uses the data efficiently, costs O(d²) per step with incremental updates, and its quality still depends on coverage and conditioning.

Replay: consecutive RL samples are strongly related, and the policy changes the data distribution while it learns. The most recent four positions (0.6–0.9) all come from one region, mean 0.75; a uniform draw such as (−0.6, 0.6, 0.8, 0.9) mixes both regions, mean 0.425. Any single random batch can still be unbalanced; uniform sampling only removes the systematic recency. Replay reuses data but cannot sample what was never collected, and old transitions come from old policies, so replay makes learning off-policy. Target network: a single-transition feedback model, not a complete DQN or a convergence proof. One weight predicts w at s and 2w at s′, and nothing anchors the next-state value (the w → 2w example of Sutton and Barto §11.2). With the live target the update is w ← w + 0.1(1.8w − w) = 1.08w, so 10 updates give 1.08¹⁰ = 2.159 and 20 give 4.661. With a frozen copy w⁻ = 1 the learner approaches the fixed target 1.8: 1.8 − 0.8 × 0.9¹⁰ = 1.521 after 10 updates. Copying then and running 10 more gives 2.314. Repeated copying still grows, only more slowly, which motivates the deadly triad on the next slide.

The Deadly Triad

Instability can arise when all three are combined:

  1. function approximation
  2. bootstrapping
  3. off-policy training

Any two are usually manageable. All three can diverge; not every run does.

Which setup contains all three ingredients?

Sources: Sutton & Barto (2018), §11.2–11.3; David Silver, Lecture 6

Be precise about the quantifier: counterexamples (Baird's, Sutton and Barto §11.2) show that convergence is not guaranteed; they do not show that every such combination fails. Remove any one ingredient and the danger recedes: Monte Carlo removes bootstrapping, a table removes shared approximation, on-policy sampling removes the distribution mismatch. Linear on-policy TD prediction has convergence results under assumptions on sampling, features and decreasing step sizes. Neither a small observed TD loss nor a finite toy run is evidence of general stability.

The bound is Sutton and Barto's equation 9.14 for the on-policy distribution: TD's asymptotic error is within a factor 1/(1−γ) of the best possible, which can be large when γ is near 1. The TD fixed point solves a projected Bellman equation rather than minimising VE, which is why TD can end above the best achievable error, as the random-walk aggregation did. The conditions include decreasing step sizes; a constant step leaves noise.

Deep Q-Networks

Fit \(\hat q(s,a,\mathbf w)\) towards targets from a frozen copy \(\mathbf w^{-}\): \[U_t=R_{t+1}+\gamma\,(1-d_{t+1})\max_{a'}\hat q(S_{t+1},a',\mathbf w^{-})\] \(d_{t+1}=1\) at true termination, otherwise 0.

Network

Observation \(\to\) hidden layers \(\to\) one \(\hat q\) per action. The features are learned by backpropagation.

Training loop

  1. Store transitions in replay
  2. Sample a minibatch
  3. Step \(\mathbf w\) towards the fixed targets
  4. Every \(C\) steps copy \(\mathbf w^{-}\leftarrow\mathbf w\)

Sources: Mnih et al. (2015); David Silver, Lecture 6

Use the 2015 DQN paper as the historical reference for experience replay plus a periodically copied target network. The update still follows target minus prediction times a gradient, now found by backpropagation, and no gradient flows through the target. The maximum makes it a Q-learning target, so DQN is off-policy even when acting ε-greedily: it has all three triad ingredients. Replay changes the sampling and the target copy changes the timing of the target (both worked through on the Replay and Target Networks slide); neither guarantees stability. Neural features scale to images but bring nonconvex optimisation and generalisation problems. The slide deliberately quotes no Atari scores; later variants and implementation details matter in practice.

Summary

\[\mathbf w\leftarrow\mathbf w+\alpha\big[\underbrace{U_t}_{\text{target}}-\hat v(S_t,\mathbf w)\big]\underbrace{\nabla_{\mathbf w}\hat v(S_t,\mathbf w)}_{\text{representation}}\]
  • features decide which states share what is learned
  • MC, TD and Sarsa differ in the target \(U_t\)
  • semi-gradient methods treat a bootstrapped target as fixed
  • approximation + bootstrapping + off-policy data can diverge
  • check terminal bootstraps, feature scales and coverage

Return to the opening question: an update changes unseen states through shared weights, by an amount set by feature similarity, x(s′)ᵀx(s) in the linear case. Ask for one failure at each layer: aliasing in the representation, accidental terminal bootstrapping in the target, a wrong sign or an excessive step in the update. Checks worth automating: W x(s) gives one value per action; a positive error raises the current prediction; inactive weights stay unchanged; the terminal bootstrap is zero; reported errors use states the policy visits; features are scaled and updates finite. Practical: compare a Q-table, simple linear features and tile-coded linear Sarsa on Mountain Car with the same interaction budget and evaluation across seeds.
