Planning: Think Before You Act

Learning

Act in the real environment and see what happens.

Example: drive a new route to work and time it.

Planning

Ask a model what would happen, without acting.

Example: try routes in a map app before driving.

A model \(\hat{\mathcal M}\) predicts what happens next: \((s,a)\;\longrightarrow\;(r,\,s')\).
Planning computes a good action from the model, with no new real experience.

The model may be given (game rules, a simulator) or learned from data (appendix).

Sources: David Silver, Lecture 8; Sutton & Barto (2018), §8.1

(2 min) Key distinction: taking an action changes the real environment; simulating an action changes only what the agent knows. In the route example the drive is real experience (S_t, A_t, R_{t+1}, S_{t+1}); the map app is a model that returns a simulated reward r and next state s′, and it can be wrong, for example about roadworks it does not know of. Everything in this lecture needs only a generative model that returns samples; it need not list transition probabilities. Formally the model is ⟨P̂, R̂⟩ with P̂(s′ | s, a) ≈ P[S_{t+1} = s′ | S_t = s, A_t = a] and R̂(s, a) ≈ E[R_{t+1} | S_t = s, A_t = a]. The appendix shows how to learn one by counting and what an inaccurate model does to a plan; Lecture 9's Dyna plans with such a learned model. "Monte-Carlo" describes sampling, not where the model came from.

Running Example: Search from Now

Plan only for the decision in front of you: look ahead from now.

  • choose A or B, then choose again
  • the model gives the payoff at each end
  • checking every branch: A is worth \(\max(0.2,0.8)=0.8\), B is worth \(0.65\)
  • so play A, then A2
Real problems have far more branches: 10 moves a turn, 6 turns ahead, is \(10^6\) end positions. We cannot check them all, so we sample.

Sources: David Silver, Lecture 8; Kocsis & Szepesvári (2006)

(2 min) This tree is the running example for the whole MCTS section. From the current state ("now") the agent chooses A or B and then chooses again; the leaves pay A1 0.2, A2 0.8, B1 0.55 and B2 0.65. One decision-maker chooses at both levels and γ = 1, so the return of a path is its leaf payoff. Checking every branch backs up the best choice at each level: A is worth max(0.2, 0.8) = 0.8 and B max(0.55, 0.65) = 0.65, so the best plan is A then A2 (highlighted). Forward search builds a tree rooted at the current state and solves only the problem that starts now; value iteration, by contrast, improves values for every state. The count in the callout: branching factor b and depth d give b^d leaves, 10^6 for b = 10, d = 6. Ask: if you could afford only 20 simulations, which branches would you simulate?

Simple Monte-Carlo Search

  1. for each move \(a\) now, imagine \(K\) episodes, playing at random afterwards
  2. score each move by its average return: \[Q(s_t,a)=\frac{1}{K}\sum_{k=1}^{K}G_k\]
  3. play the move with the best score

\(s_t\): the current state · \(K\): episodes per move · \(G_k\): return of episode \(k\)

Example, random play after the first move:

  • A: half the episodes end at A1 (0.2), half at A2 (0.8), so \(Q=0.5\)
  • B: 0.55 or 0.65, so \(Q=0.6\)
  • it plays B, but A is better
Two fixes: remember results in a tree so that the follow-up play improves, and choose where each simulation goes: UCB1.

Sources: David Silver, Lecture 8; Kocsis & Szepesvári (2006)

(2 min) Also called flat Monte-Carlo or rollout search. As K grows, Q(s_t, a) converges to q_π(s_t, a), the value of a under the random rollout policy π, not the optimal value q_*: here q_π(A) = (0.2 + 0.8)/2 = 0.5 and q_π(B) = (0.55 + 0.65)/2 = 0.6, while the optimal values are 0.8 and 0.65. Random follow-up play makes A look bad because half the time it blunders into A1. There are two separate weaknesses. The follow-up choices never improve; a tree whose statistics improve the choices inside it fixes this. And the simulations are split evenly whatever they reveal; UCB1 fixes this by sending more simulations to moves that look promising or are still uncertain. The interactive comparison later in the lecture runs both methods on this tree.

UCB1: Which Option Next?

The Multi-Armed Bandit

A row of slot machines (arms). Each turn you pull one arm and receive a random reward.

  • arm \(a\) pays on average \(q_*(a)\), which is unknown
  • goal: as much total reward as possible
  • exploit: pull the arm that looks best so far
  • explore: pull another arm to learn about it

Our example (hidden from the agent):

Arm123
\(q_*(a)\)0.30.50.7

A pull pays 1 with probability \(q_*(a)\), otherwise 0.

In MCTS every node faces this problem: its moves are the arms, and one simulation is one pull.

Sources: Sutton & Barto (2018), Chapter 2; Auer, Cesa-Bianchi & Fischer (2002)

(2 min) The name comes from slot machines, "one-armed bandits". A bandit is a one-state decision problem: there is no next state, so the only difficulty is learning which arm is best while collecting reward. q_*(a) is the true mean reward of arm a, the action value of this one-state problem; Lecture 9 uses the same notation. The three arms in the table are the running example for the whole section; their means are hidden from the agent, and the interactive slide can reveal them. Ask for everyday examples: choosing a restaurant, a route to work, which advert to show. Connect to MCTS now: at the root of the running tree, A and B are two arms, and a simulation that returns G is one pull that paid G.

What does greedy do from pull 4 on?

One unlucky pull can hide the best arm for ever. We need a reason to retry arms we know little about.

(2 min) Answer: Arm 1 for ever. Greedy pulls the arm with the highest sample average. Arm 1's average is 1 after its first pull and drifts towards 0.3, but never reaches 0 because one of its rewards is 1; Arms 2 and 3 sit at 0 and are never pulled again. Greedy therefore commits to the worst arm. These are the real first pulls of the interactive slide (seed 846): at c = 0 its rule is greedy, and after 200 pulls Arm 1 has 198 of them. The lesson is not about bad luck: any rule that never revisits an arm can be fooled by one unlucky sample. The fix is to give extra credit to arms whose averages rest on few pulls.

The UCB1 Rule

Pull every arm once. After that, always pull the arm with the highest score:

\[\text{score}(a)=\underbrace{Q(a)}_{\text{exploit}}+\underbrace{c\sqrt{\frac{\ln t}{N(a)}}}_{\text{explore (bonus)}}\]
SymbolMeaning
\(Q(a)\)average reward from arm \(a\) so far
\(N(a)\)number of times arm \(a\) has been pulled
\(t\)total pulls so far, all arms: \(t=\sum_a N(a)\)
\(\ln\)natural logarithm
\(c\)exploration constant: \(\sqrt2\) in the original UCB1; \(1\) in our examples

Sources: Auer, Cesa-Bianchi & Fischer (2002); Sutton & Barto (2018), §2.7

(3 min) Read the formula left to right with the table. The first term exploits: it is the average reward seen so far. The second explores: it is large when N(a) is small, that is, when the average rests on few pulls. Every arm is pulled once before the formula is used, because N(a) = 0 would divide by zero; equivalently, an untried arm's score counts as infinite. Auer, Cesa-Bianchi and Fischer (2002) define UCB1 as x̄_j + √(2 ln n / n_j) for rewards in [0, 1], which is c = √2 here. This deck uses c = 1 so that the hand calculations are easy; in practice c is tuned to the scale of the rewards. Notation bridge to Lecture 9: there the bonus is written U_t(a) = √(c ln t / N_t(a)) with c inside the root, so its c = 2 is this deck's c = √2; t, N(a) and Q(a) are the same quantities. UCB stands for upper confidence bound. Lecture 9 derives the bonus from Hoeffding's inequality and proves that UCB1's regret grows only logarithmically.

The score is an optimistic guess of the arm's true mean: an upper confidence bound. Either the arm really is good, or pulling it shows it is not and its bonus shrinks.

Sources: Auer, Cesa-Bianchi & Fischer (2002); David Silver, Lecture 9

(2 min) Left: the standard error of an average of N samples shrinks like 1/√N, and the bonus has the same shape, so it measures how uncertain Q(a) still is. Quadrupling N(a) halves the bonus: at t = 100 and c = 1, √(ln 100 / N(a)) = √(4.605 / N(a)) = 2.15, 1.07, 0.54 and 0.27 for N(a) = 1, 4, 16 and 64. Right: ln t keeps rising, so an arm that is not being pulled slowly gains bonus and is eventually tried again; no arm is abandoned for ever, unlike under greedy. Because ln t grows so slowly, poor arms receive only a slowly growing number of extra pulls, which is why UCB1's regret grows like ln t (Lecture 9). Optimism corrects itself: if the arm is good we gain reward, and if it is not, pulling it shrinks its bonus until another arm leads.

Quick Check: After a Pull

UCB1 pulls Arm 2.

The reward equals Arm 2's current average, so \(Q(2)\) does not change.

What happens to the scores?

(1 min) Answer: Arm 2's score falls and the others rise a little. N(2) grows by one, so Arm 2's bonus shrinks; with Q(2) unchanged its score falls. (Once every arm has been tried this always holds for the pulled arm: N ln(t + 1) < (N + 1) ln t whenever t ≥ 3 and N ≤ t.) The total t grows for every arm, so ln t rises and the arms that were not pulled gain a little bonus. This is why the bars in the interactive slide take turns: the pulled arm drops, the others creep up, and an arm that is never pulled eventually leads.

MCTS: One Iteration, Four Steps

MCTS builds a search tree one path at a time. Each iteration has four steps. After many iterations, it plays the root action with the most visits.

The Four Steps

  1. Selection. Start at the root. While the current node is fully expanded, go down to the child with the highest UCB1 score. Stop when you reach a node that still has an untried action, or a terminal state.
  2. Expansion. Add one new child for one of the untried actions.
  3. Simulation (rollout). From the new node, play random actions until the episode ends. Record the return \(r\).
  4. Backpropagation. Go back up the path to the root. At each node, do \(N \mathrel{+}= 1\) and \(W \mathrel{+}= r\).

Repeat until the budget (number of iterations or time) is used. Then play the root child with the highest \(N\).

(2 min) The same four phases as the stepper, stated as an algorithm. Selection only descends through fully expanded nodes, so every child is tried once before UCB1 compares them. Expansion adds one node per iteration. The rollout states are not stored. Backpropagation adds the same return r to every node on the path, which is correct here because the reward arrives only at the end of the episode. The deck's own Four Phases slide calls step 3 Evaluate, because a value network can replace the rollout (AlphaZero, later in the lecture).

UCB1: The Selection Rule

\[\text{UCB1}(i) = \underbrace{\frac{W_i}{N_i}}_{\text{exploit}} + \underbrace{c\sqrt{\frac{\ln N_{\text{parent}}}{N_i}}}_{\text{explore}}\]
  • Exploit term (Q): the average return of the child so far.
  • Explore term: large when a child has few visits compared to its parent. It gets smaller each time you visit the child. It gets slowly larger each time you visit a sibling, because of ln.

(2 min) W_i is the total return of child i, N_i its visit count and N_parent the visit count of its parent, so W_i / N_i is the mean return Q. This is the UCT score of the earlier From Bandits to Trees slide written per child: W_i / N_i = Q(s, a), N_i = N(s, a) and N_parent = N(s). Visiting a sibling increases N_parent but not N_i, so the bonus grows like √(ln N_parent): slowly. The next slide covers c and unvisited children.

UCB1: The Selection Rule (continued)

  • \(c\): sets the balance between the two terms. \(c=\sqrt2\) is the theoretical value when returns are in \([0,1]\). If your returns use a different range, normalise them or tune \(c\).
  • An unvisited child has \(\text{UCB1}=\infty\), so each child is tried once before UCB1 starts to compare them.
Key point: in iteration 5 of the stepper, A has \(Q=0\) and B has \(Q=0.67\), but A wins because its bonus is larger. Thus MCTS does not lock onto an early lucky result.

(1 min) c = √2 is Auer et al.'s UCB1 constant for rewards in [0, 1]; the stepper and the Python example use it. The deck's UCB1 section uses c = 1 for easier arithmetic; both are the same rule with a different balance. The key point refers to step 17 of the stepper: A scores 0.00 + 1.67 = 1.67 against B's 0.67 + 0.96 = 1.63.

MCTS in Python (1/3)

Toy task: choose 3 bits, one at a time. The reward is the fraction of bits that match the target (1, 0, 1).


import math, random

TARGET = (1, 0, 1)

def actions(s):  return [] if len(s) == len(TARGET) else [0, 1]
def step(s, a):  return s + (a,)
def reward(s):   return sum(x == t for x, t in zip(s, TARGET)) / len(TARGET)

class Node:
    def __init__(self, state, parent=None, action=None):
        self.state, self.parent, self.action = state, parent, action
        self.children, self.untried = [], actions(state)
        self.N, self.W = 0, 0.0

    def ucb1(self, c=math.sqrt(2)):
        if self.N == 0:
            return float("inf")
        return self.W / self.N + c * math.sqrt(math.log(self.parent.N) / self.N)

(1 min) A state is the tuple of bits chosen so far; actions are 0 and 1 until three bits are chosen, and the reward scores the finished tuple against the target. Each Node stores N and W; ucb1 returns infinity for an unvisited node, so every child is tried once, and otherwise computes W/N plus the exploration bonus with c = √2.

MCTS in Python (2/3)


def mcts(root_state, iterations=500):
    root = Node(root_state)
    for _ in range(iterations):
        node = root
        # 1. Selection
        while not node.untried and node.children:
            node = max(node.children, key=Node.ucb1)
        # 2. Expansion
        if node.untried:
            a = node.untried.pop(random.randrange(len(node.untried)))
            node.children.append(Node(step(node.state, a), node, a))
            node = node.children[-1]

(1 min) Each of the 500 iterations starts at the root. Selection descends while the node has no untried actions and has children, picking the child with the largest ucb1. Expansion pops a random untried action and adds its child, which becomes the node the rollout starts from. The loop continues on the next slide.

Points to Remember

  • MCTS needs a simulator: a function that gives the next state for a state and an action. It does not learn a model.
  • A random rollout is the simplest value estimate. You can replace it with a heuristic, a value network or a short planned rollout. This change usually gives a large improvement.
  • After you play a move, you can reuse the subtree under the chosen child for the next decision.
  • For stochastic environments, one node per action is not sufficient. You need chance nodes or open-loop MCTS.

(2 min) The simulator can be exact (game rules) or a learned model, as in the appendix; MCTS itself only queries it. Replacing random rollouts with a value network is AlphaZero's change, later in the lecture. Subtree reuse keeps the statistics already gathered for the move actually played. With stochastic transitions, one action can lead to several next states, so a node per action mixes them: chance nodes branch on the outcome, and open-loop MCTS stores action sequences instead of states.

From Bandits to Trees: UCT

MCTS treats every node \(s\) of its tree as a bandit: the moves are the arms, and one simulation through \(s\) is one pull.

\[\text{UCT}(s,a)=Q(s,a)+c\sqrt{\frac{\ln N(s)}{N(s,a)}}\]
UCB1 (bandit)UCT (node \(s\))Meaning in the tree
arm \(a\)move \(a\)a child of \(s\)
\(Q(a)\)\(Q(s,a)\)average return of simulations that took \(a\) at \(s\)
\(N(a)\)\(N(s,a)\)number of simulations that took \(a\) at \(s\)
\(t\)\(N(s)\)number of simulations through \(s\)
rewardreturn \(G\)what one simulation scored

Sources: Kocsis & Szepesvári (2006); David Silver, Lecture 8

(2 min) UCT, "upper confidence bounds applied to trees", is Kocsis and Szepesvári's (2006) algorithm: UCB1 run at every node of the search tree. Go through the table row by row: nothing is new except that the "reward" of a pull is the return G of a whole simulation. N(s) is the parent's visit count: at the root it is the sum of the children's visits, and deeper in the tree it also counts the simulation that expanded the node. Untried moves are expanded before UCT is used, as in UCB1. In full, Q(s, a) = (1/N(s, a)) Σ_k Σ_u 1(S^k_u, A^k_u = s, a) G^k_u: the average, over simulations k that passed through edge (s, a), of the return from that point. With a suitable c, Kocsis and Szepesvári show that Q(s_t, a) → q_*(s_t, a) as the number of simulations grows (finite-horizon or truncated discounted MDPs with bounded rewards); this says nothing about a finite budget. Unlike a bandit arm, a node's returns drift as the search below it improves, so the bandit guarantee does not transfer unchanged; their proof handles the drift.

Four Phases of a Simulation

Tree policy (inside the tree): UCT, which improves as the statistics grow.

Rollout policy (beyond the tree): fixed, e.g. random moves.

Repeat until the budget runs out, then play the root move with the most visits.

Sources: Browne et al. (2012), MCTS survey; Kocsis & Szepesvári (2006)

(3 min) One simulation has four phases. Select: from the root, follow UCT through nodes whose moves have all been tried, and stop at a node with an untried move (or at a terminal state). Expand: store one untried child as a new node. Evaluate: estimate the new node's value, here by a random rollout to the end of the episode, which returns G; the states visited by the rollout are not stored. Back up: every node on the stored path adds 1 to N and G to W. The tree policy improves because its statistics improve; the rollout policy stays fixed. Implementations package the phases differently (several nodes per expansion, a value network instead of a rollout, as in AlphaZero later) but the four roles remain. Silver describes MCTS as Monte-Carlo control applied to simulated experience that starts now: evaluation by averaging returns, improvement by UCT. The commitment rule is the subject of the Choosing the Move slide.

Backing Up a Return

When a simulation returns \(G\), every stored edge on its path updates:

\[N\leftarrow N+1,\qquad W\leftarrow W+G,\qquad Q=W/N\]

\(N\): visits · \(W\): total return · \(Q\): mean return · \(G\): this simulation's return

Example: an edge has 3 visits and a total return of 1.5. A new simulation returns \(G=0.8\):

Sources: Kocsis & Szepesvári (2006); David Silver, Lecture 8

(2 min) Ask for the new Q before revealing the row. With the same edge, G = 0 gives Q = 1.5/4 = 0.375 and G = 1 gives 2.5/4 = 0.625: one return moves Q a quarter of the way towards G, never beyond it. A max backup would jump to 0.8 and keep the luckiest rollout, which overestimates noisy moves. The incremental form Q ← Q + (G − Q)/N, with the updated N, is the same thing: 0.5 + (0.8 − 0.5)/4 = 0.575. With intermediate rewards, each edge needs its own return-to-go, accumulated backwards along the path as G ← R + γG; copying one terminal reward along the path is valid only under the single-agent, terminal-reward, γ = 1 convention of the running example. Two-player games are in the next section.

Choosing the Move

After the search

  • play the root move with the most visits \(N(s_t,a)\)
  • running tree, 200 simulations: A has 153 visits, B 47, so play A
  • no bonus here: uncertainty is a reason to search a move, not to play it

Why MCTS works well

  • selective: simulations go where they matter
  • needs only a simulator, no evaluation function
  • anytime: stop whenever, use the current answer
  • the subtree is reused after the real move
Case study: computer Go, where simulated games are cheap but judging a position by hand is hard.

Sources: David Silver, Lecture 8; Browne et al. (2012)

(2 min) Root decision rules: most visits, a_t = argmax_a N(s_t, a) (used in the demos), highest mean Q (Silver's slide), or sampling in proportion to visits during training (AlphaZero). Most visits is robust because a move collects visits only if its score stayed high over many simulations. Never add the exploration bonus to the real decision; the exercise at the end makes this distinction. The advantages are qualitative: best-first search that concentrates on promising lines; values computed from the current state rather than for every state, unlike dynamic programming; sampling avoids enumerating b^d leaves; only a black-box simulator is needed; anytime, meaning it can be interrupted and still return its current answer (not that every extra sample improves it); parallelisable with care, since simultaneous simulations see the same stale statistics. Silver's case study is Go: a position's value is estimated by the mean outcome of simulated games, and the tree grows asymmetrically towards promising moves. This deck makes no performance claim.

Quick Check: Two-Player Games

In a zero-sum game the opponent moves at every other level, and picks what is worst for us.

  • all stored returns are for the root player
  • at an opponent node, one move gives +0.8 and the other −0.4 to the root player
  • ignore exploration

Which move does a rational opponent choose?

Sources: Kocsis & Szepesvári (2006); David Silver, Lecture 10: Classic Games

(2 min) Answer: −0.4. Three kinds of node: our decision maximises; a chance node averages under its probabilities (for outcomes +1 and −1 with p(+1) = 0.75, the value is 0.75 − 0.25 = 0.5); a zero-sum opponent minimises our value (−1 for every p). Treating an opponent as chance changes the problem. In MCTS there are two equivalent conventions: store values from the perspective of the player to move at each node and flip the sign of G during backup ("negamax"), so every node maximises; or store root-player values and let opponent nodes minimise, with the exploration bonus subtracted. Never maximise root-player values at both kinds of node. Stochastic transitions, same-player turns and intermediate rewards need a convention that matches the game. Ask which assumption changed between the running tree and this slide.

AlphaZero: Learned Guidance

One network guides the search: \((\mathbf p,\,v)=f_\theta(s)\)

  • prior \(P(s,a)\): which moves to search first
  • value \(v(s)\): scores a new leaf instead of a rollout

Selection (PUCT):

\[Q(s,a)+c\,P(s,a)\,\frac{\sqrt{N(s)}}{1+N(s,a)}\]

Same idea as UCT: mean plus a bonus that shrinks with the move's visits, now scaled by the prior. The \(1+\) keeps an unvisited move's score finite.

Search improves the move choices; self-play games train the network.

Sources: Silver et al. (2017), AlphaZero, algorithm description

(2 min) The conceptual change is two learned outputs, not a bigger rollout budget. The policy head gives prior move probabilities P(s, a); the value head replaces random rollouts at a new leaf. Search produces visit-count targets for the policy and games produce outcome targets for the value. The network does not replace the known game rules: AlphaZero still uses the real legal moves and transitions. Illustrative PUCT numbers (not AlphaZero's hyperparameters): N(s) = 12, c = 2; A with Q = 0.2, N = 10, P = 0.7 scores 0.2 + 2 × 0.7 × 3.464 / 11 = 0.64; B with Q = 0.6, N = 2, P = 0.3 scores 0.6 + 2 × 0.3 × 3.464 / 3 = 1.29, so B is searched next; A would need P(s, A) ≳ 0.92. A prior of exactly zero can suppress a move under this score, so practical systems add exploration noise at the root. Training, exploration noise, terminal handling, player perspective and evaluation protocol all matter; this slide states mechanisms only.

What Is a Model?

A model \(\hat{\mathcal M}\) predicts what the environment does next: given a state and an action, it gives a reward and a next state. \[(s,a)\;\longrightarrow\;(r,\,s')\]

Example: a delivery robot in a corridor. Its model says “forward” reaches the door 80% of the time and slips back 20%, and every move costs 1.

  • predicting the reward is a regression problem
  • predicting the next state means estimating a probability distribution
  • two sources of error: the model, then the planned values

Sources: David Silver, Lecture 8; Sutton & Barto (2018), §8.1

Formally the model is a pair ⟨P̂, R̂⟩ with P̂(s′ | s, a) ≈ P[S_{t+1} = s′ | S_t = s, A_t = a] and R̂(s, a) ≈ E[R_{t+1} | S_t = s, A_t = a]: the course's Lecture 1 model, now estimated. Learning s, a → s′ is density estimation. We assume the state and action spaces are known and treat model learning as supervised learning from the pairs (S_t, A_t) → (R_{t+1}, S_{t+1}). Examples: table lookup, linear expectation or linear Gaussian models, Gaussian processes, neural networks. Advantages: supervised learning methods apply, and uncertainty about the model can be reasoned about explicitly. Disadvantage: the planned value inherits the model's error as well as its own approximation error.

Table Lookup Model

Count what happened after each state and action, and use the frequencies.

Example: the robot tried “forward” 20 times.

What happenedCountModel
reached the door1616/20 = 0.8
slipped back44/20 = 0.2
\[\hat{\mathcal P}(s'\mid s,a)=\frac{N(s,a,s')}{N(s,a)}\]

The reward model is the average reward that followed: here −1.

Alternative: store every real transition and replay one that matches \((s,a)\) (Dyna, Lecture 9).

Sources: David Silver, Lecture 8; Sutton & Barto (2018), §8.1

In full: P̂(s′ | s, a) = (1/N(s, a)) Σ_t 1(S_t, A_t, S_{t+1} = s, a, s′) and R̂(s, a) = (1/N(s, a)) Σ_t 1(S_t, A_t = s, a) R_{t+1}, summing over all recorded time steps: observed frequencies and mean rewards, the maximum-likelihood estimates. Before (s, a) has been tried, N(s, a) = 0 and the estimate is undefined, not zero. The stored-transition version is the sample model used by Dyna-Q (Lecture 9): it reproduces the empirical distribution without ever writing down the probabilities. Worked example: 16 of the 20 tries reached the door, so P̂(door | corridor, forward) = 16/20 = 0.8 and P̂(back) = 0.2, the 80% the previous slide quoted; every move cost 1, so R̂ = −1. More samples reduce uncertainty in the statistical sense, but a single new observation can move the estimate away from the truth.

Planning with a Model

Solve the model's MDP with any planner: value iteration, policy iteration, tree search.

Each step is a backup: the reward now, plus the discounted average value of where the model says you land.

Example: a move costs 0.1. The model says it reaches a state worth 1 with probability 0.6, otherwise a state worth 0; \(\gamma=0.9\). \[Q(s,a)=-0.1+0.9\,(0.6\times1+0.4\times0)=0.44\]

Sources: David Silver, Lecture 8; Sutton & Barto (2018), §8.1

The general backup is Q(s, a) = R̂(s, a) + γ Σ_{s′} P̂(s′ | s, a) V(s′). This is one expected backup with supplied successor values (they are not learned here). With γ = 0.9: Q = −0.1 + 0.9 × 0.6 = 0.44, and Q = 0 when the success probability is 0.1/0.9 ≈ 0.111; at γ = 0 only the immediate reward −0.1 remains, so no probability breaks even. The two outcomes are stochastic transitions, so they are averaged: the planner cannot choose the successful one. Distinguish uncertainty about which successor occurs (the probability) from uncertainty about whether the model's probability is right (the inaccurate-model slide). The next slide replaces the sum over successors by samples.

Sample-Based Planning

Use the model only to generate experience, then learn from it with model-free RL: Monte-Carlo control, Sarsa, Q-learning.

Example: the move from the last slide. Instead of averaging over both outcomes, ask the model for 10 samples. If 6 reach the good state the estimate is \(-0.1+0.9\times\tfrac{6}{10}=0.44\); if 7 do, it is 0.53.

  • samples concentrate on likely outcomes
  • often cheaper than summing over every outcome
  • needs only a simulator that produces samples

Sources: David Silver, Lecture 8; Sutton & Barto (2018), §8.1

Formally: S_{t+1} ∼ P̂(· | S_t, A_t) and R_{t+1} = R̂(S_t, A_t), then any model-free update. In the example the estimate from 10 samples is −0.1 + 0.9 × (successes/10), so it varies from sample to sample around 0.44; more samples narrow the spread. Full-width planning (value iteration) sums over every successor. Sample-based planning replaces the sum by samples, exactly as Monte-Carlo and TD learning replace it in model-free prediction, so the whole model-free toolbox from Lectures 4–5 becomes a planning method. The efficiency claim is a tendency, not a theorem: rare but important outcomes may be sampled late. The next slide is Silver's AB example.

Interactive: Planning with an Inaccurate Model

Risky: pays 2 on success, 0 on failure; real success probability 0.6. Safe: always pays 1.3. Whisker: model estimate ± 2 standard errors after n simulations.

A planner can do no better than the optimal policy of the approximate MDP.

Raise n from 10 to 1000. Which error shrinks, and which does not? Which model probabilities choose wrongly?

Sources: David Silver, Lecture 8; Sutton & Barto (2018), §8.3

This is an analytical calculator, not a Monte-Carlo run. A simulated risky reward under the model is 2 × Bernoulli(p), where p is the model's success probability, so the mean of n independent simulations has expectation 2p and standard error SE = 2√(p(1−p)/n); the black whisker is the band 2p ± 2 SE, cut to the possible range 0–2. The true risky value is 1.2, below the safe 1.3. At the default p = 0.8 the model predicts 1.60, a bias of +0.40 at every n. The ±2 SE band is 1.09–2.00 at n = 10 (it contains 1.30, so a 10-sample estimate could by chance prefer safe), 1.44–1.76 at n = 100 and 1.55–1.65 at n = 1000: more simulations shrink the sampling error as 1/√n and make the wrong preference more certain, but leave the bias unchanged. Any model with p > 0.65 (0.70 and above on the slider) prefers the wrong action; p = 0.65 ties; p ≤ 0.6 chooses safe, though p < 0.6 is also biased. The standard error excludes parameter uncertainty and misspecification. Silver's two remedies: fall back on model-free RL when the model is wrong, or reason explicitly about model uncertainty.

Formally: simulate K episodes {s_t, A^k_t, R^k_{t+1}, S^k_{t+1}, …, S^k_T}, k = 1, …, K, from the model, all starting at the current real state s_t, and apply a model-free method to them. Silver's Dyna-2 combines a long-term memory learned from real experience with a short-term memory updated by TD search during each decision. TD search and Dyna-2 are follow-up reading; the lecture develops Monte-Carlo search.

Where the Rollout Stops

A rollout cut off after \(h\) steps must still score the state where it stops: the rewards collected so far, plus a discounted estimate \(\hat v\) of the rest.

Example, \(\gamma=0.9\): the short route pays 0.45 after one step; the long route pays 1 after six steps, earlier rewards 0.

Evaluation of the long routeEstimateSearch picks
full rollout to the end\(\gamma^{5}\approx0.59\)long (correct)
cut at \(h=3\), \(\hat v=0\)\(0\)short (wrong)
cut at \(h=3\), \(\hat v=\gamma^{2}=0.81\)\(0.9^{3}\times0.81\approx0.59\)long (correct)
A computational cutoff is not a terminal state: leaving out \(\hat v\) assumes it is 0.

Sources: Sutton & Barto (2018), Chapter 8; David Silver, Lecture 8

In symbols, the truncated return is G = Σ_{k=1..h} γ^(k−1) R_{t+k} + γ^h v̂(S_{t+h}). The long route's reward arrives as R_{t+6}, so its exact return is γ⁵ (0.590 at γ = 0.9), not γ⁶. With h < 6 the estimate is γ^h v̂(S_{t+h}), because the first h rewards are 0. At h = 3 and γ = 0.9 the exact remaining value is γ² = 0.81, and inserting it gives γ³ × 0.81 = 0.59049, the exact return; any v̂ above 0.45/0.729 ≈ 0.617 makes the search pick the long route. With v̂ = 0, an omitted bootstrap is a hidden zero-value assumption. At h = 6 the episode terminates and no v̂ is needed. At γ = 0.5 the short route really is better (0.5⁵ ≈ 0.031), so a deeper search need not choose the long route; the break-even discount is 0.45^(1/5) ≈ 0.852. In MCTS the leaf evaluation may be a rollout, a truncated rollout plus v̂, or v̂ alone (a value network, as on the AlphaZero slide).

Chance and Opponent Nodes

Two outcomes, worth +1 and −1 to the root player. Who picks the branch decides the value:

NodeRuleValue to the root player
our decisionmaximise\(\max(+1,-1)=+1\)
chance, \(p(+1)=0.75\)average\(0.75(+1)+0.25(-1)=0.5\)
zero-sum opponentminimise\(\min(+1,-1)=-1\)
Chance nodes sample outcomes; opponents choose them. Treating an opponent as chance changes the problem.

Sources: Kocsis & Szepesvári (2006); David Silver, Lecture 10: Classic Games

Three node types: our decision (maximise), chance (average under the probability law: 2p − 1 for a general p, 0.5 at p = 0.75) and an opponent's decision. A random-opponent model gives an expectation; a perfect-information zero-sum adversary chooses the best response, −1 for every p, so no p makes the opponent's branch worth more than −1. In MCTS, opponent nodes either maximise values stored from the opponent's perspective, or minimise root-perspective values with a matching exploration bonus. Never maximise root-player Q at both. With alternating player-to-move values, zero-sum returns change sign during backup; with a fixed root perspective, the stored sign stays and the selection rule changes. Chance nodes sample outcomes; they never choose optimistic ones.

Before Trusting a Search Result

Model and information

  • Does the model reproduce the relevant consequences?
  • Are chance and opponent nodes distinct?
  • Could the search see hidden information?

Computation and evaluation

  • Was a cutoff mistaken for termination?
  • Were values backed up in one clear convention?
  • Does the choice survive other seeds and budgets?
A consistent planner can still solve the wrong decision problem.

Sources: Kocsis & Szepesvári (2006); David Silver, Lecture 8; Silver et al. (2017)

The UCT paper gives consistency results under particular finite-horizon or discounted MDP and bounded-reward assumptions, not a finite-budget guarantee for any learned-model or neural implementation. Hidden-information games need information-state reasoning; searching with the opponent's actual hidden cards is not valid play. Distribution shift in learned models and rare outcomes matter especially outside games. Numerical correctness, model validity and application performance are separate checks.
